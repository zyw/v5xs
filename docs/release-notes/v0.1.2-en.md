# v5xs 0.1.2

> Released 2026-10-26 · Build 4 · Requires macOS 14.0 or later

The headline of this release: **"Terminate" and "Force Quit" in the process list now actually work.** It also adds a **configurable monitoring refresh rate**, plus layout fixes for the settings window and battery rings.

## New

### Monitoring refresh rate is now configurable

Settings gains a "Monitoring" section with four sampling rates:

| Rate | Interval | Best for |
| --- | --- | --- |
| Fastest | 0.5 s | Spotting transient peaks, compiles, recordings |
| Standard | 1 s | Default; balances precision and overhead |
| Relaxed | 2 s | Everyday viewing with lower overhead |
| Power saver | 5 s | Trends only, lowest cost |

Changes take effect **immediately**, with no restart. The status line at the bottom of the panel (e.g. `v0.1.2 · updates every 2 s`) follows the selected rate. Higher rates give smoother charts but cost a little more CPU, so pick whatever suits your machine. The old "low latency" toggle is migrated to the matching rate, so existing preferences are preserved.

## Fixes

### Health score stuck on "Collecting"

The health score at the top of the panel could sit on "Collecting" indefinitely. A premature return in the sampling timer setup meant the timer was never created, so the sampling loop never ran and the CPU / memory data behind the score stayed empty. Fixed, with a regression test to keep it fixed.

### Terminate / Force Quit did nothing for most processes

Both actions failed silently on most rows, or showed a misleading "process has already exited" alert. In a live check, 4 out of the top 5 rows in the list could not be acted on at all.

Two separate defects in the pre-kill identity check were responsible:

- **Non-GUI processes never passed the check.** The code used `NSRunningApplication(processIdentifier:)` as a guard, but that API only knows GUI apps with a `.app` bundle. For java processes, helpers and daemons it returns `nil` — measured at 83% of 637 processes on a live system. Those are exactly the processes filling this list, so the guard returned early and no signal was ever sent.
- **Paths were truncated by the kernel.** The check compared `ps -o comm=` output against a full path, but `comm` comes from the kernel's `p_comm`, which is capped at 16 bytes. Long paths are necessarily truncated (e.g. `Google Chrome He`) and can never equal the full path.

Identity is now resolved through `libproc` / `sysctl`, reading the **full executable path** and the **start time in epoch seconds**, with no dependency on `ps` text or `NSRunningApplication`. The start time acts as a second check against PID reuse: if the process is replaced during confirmation, the action is refused rather than killing the wrong process.

The two actions now also behave differently:

- **Terminate** sends `SIGTERM`, letting the process clean up and exit on its own.
- **Force Quit** sends `SIGKILL`, which cannot be intercepted. Identity is re-verified right before the signal is sent.

Insufficient permissions (another user's process, or a protected system process) now produce a specific explanation instead of a generic failure.

### "Show in Finder" failed for non-GUI processes

Same root cause. It now falls back to walking up the executable path to find the enclosing `.app` directory.

## Interface changes

### Hover highlight in the process list

Hovering a row lights up the whole row, turns the process name mint green, and reveals the action menu. The hover target covers the full row width, so moving the cursor into the gap between columns does not break the highlight.

### Dimmed text in the process list

Body text now sits lower in contrast so the list no longer competes with the rest of the card. The amber warning for CPU above 50% is preserved as a genuine signal. Contrast against the card background is 4.66:1, which meets the WCAG AA threshold for small text — dimmer, but still legible.

### Settings window no longer scrolls

The settings content actually needs 583pt of height, but the window was pinned to 500pt, so a scrollbar appeared the moment it opened. The window now sizes itself to its content. Its minimum height matches the content too, bounded by the available screen height so it never extends past the display.

### Battery ring size and layout

The mouse and keyboard battery rings were 49pt and pushed against the divider above them:

| | Before | After |
| --- | --- | --- |
| Diameter | 49pt | 34pt |
| Stroke width | 5pt | 4pt |
| Icon size | 17pt | 12pt |
| Spacing between rings | 10pt | 14pt |

Both rings are now vertically centered against the MacBook block on the left, with more breathing room between them.

## Update feed

The auto-update manifest is now generated in CI at release time **from the DMGs actually attached to the release**, instead of relying on a committed `dist/update.json`. That directory is listed in `.gitignore`, which previously made the publish workflow fail every time. File sizes and SHA-256 values in the manifest are therefore always byte-for-byte consistent with the shipped installer.

## Install

Download `v5xs-0.1.2-macOS-26.4-arm64.dmg` from [Releases](../../releases) and drag v5xs into your Applications folder.

Users on an older build can click "Check for Updates" in Settings to get the download link.

## Known limitations

- The build is ad-hoc signed, so Gatekeeper may block the first launch. Allow it under System Settings → Privacy & Security.
- The process list shows individual processes, not whole applications. Terminating a helper such as IDEA's `fsnotifier` will not close the main window — this is expected.
- CPU / GPU temperatures are only read on the validated model (Mac14,2).
