# v5xs 0.1.3

> Released 2026-10-27 · Build 5 · Requires macOS 14.0 or later

The headline: **v5xs can now download, verify, and install updates by itself** — no more fetching DMGs from the Releases page by hand. This release also adds five new menu bar animals and a dedicated icon for paused animation.

## New

### Automatic updates: download, verify, replace, restart

In **Settings → Updates**, clicking "Download and Install" runs the whole flow:

```
download → verify → mount → replace → restart
```

Usually takes a few seconds. The original "Download manually" entry is still there as a fallback if automatic installation can't proceed.

### Three configurable toggles

| Toggle | Default | What it does |
| --- | --- | --- |
| Check for updates automatically (every 24 hours) | On | Silent background check |
| Download new versions automatically | Off | Downloads and verifies, but still asks before installing |
| Restart and install automatically when ready | Off | Quits and restarts as soon as the package is ready |

Each depends on the previous one: turning off automatic checks disables automatic download.

**Auto-install is off by default on purpose** — it makes the app quit and restart while you're working, so it should be an explicit choice.

### Signed update manifests

Automatic installation hands execution permission to a remote server, so the manifest is now signed with **Ed25519**, with the public key compiled into the app.

This matters: the SHA-256 inside a manifest comes from the same HTTPS response as the manifest itself. If the feed is hijacked, both can be swapped together and the checksum proves nothing. A signature means an attacker also needs the private key.

Before installing, v5xs checks:

- The manifest signature (unsigned or mismatched manifests are rejected)
- Package size and SHA-256 (failures delete the file — it is never installed)
- The bundle identifier inside the package (prevents swapping in a different app)
- Free disk space, whether the app runs from a read-only location, and whether multiple instances are running

### Five new menu bar animals

"Sprinter", "Bolt", "Dragon", "Panda" and "Tiger" running animations, with localized names in Simplified Chinese, Traditional Chinese and English.

### A dedicated icon while animation is paused

Pausing used to freeze the animal on its current frame, which looked like a stalled animation. Now it shows the v5xs logo silhouette, making "paused" unmistakable. Resuming switches back to your chosen animal.

## Fixes

### "Check for Updates" opened the wrong settings page

The menu item opened Settings but left it on "General", so it looked like nothing happened. It now jumps to the Updates section.

The opposite problem is fixed too: after jumping to Updates via "Check for Updates", clicking "Settings" used to stay on the Updates page. Each entry point now maps to a definite section — "Settings" always opens General.

### Menu bar icon showed the wrong state

Launching the app or switching animals would display the animated animal even while paused, silently undoing the paused state. All icon updates now go through one code path.

## Interface changes

### Settings moved to a sidebar layout

With more settings, a single scrolling page no longer worked. Settings are now split into:

`General` · `Monitoring` · `Updates` · `Language` · `About`

### Settings window sizes itself

The window height follows its content, so no scrollbar appears; it is also bounded by the available screen height so it never extends off a small display.

## Release tooling and security

### Update manifest is generated in CI

The manifest no longer relies on a committed `dist/update.json` (that directory is gitignored, which previously made the publish workflow fail every time). CI now computes it from the DMGs actually attached to the release, so sizes and SHA-256 values always match the shipped installer byte for byte.

### The publish workflow now signs

It reads the private key from a repository secret, signs the manifest, then **re-verifies with the public key from the repo** to confirm the key pair matches — a mismatch would make every installed client reject the update, so it must be caught before release. The private key is removed when the job finishes.

> **Note**: the publish workflow intentionally fails when the `V5XS_UPDATE_SIGNING_KEY` secret is not configured. Shipping an unsigned manifest would make updates fail silently for users, which is far harder to diagnose than a failed release job. See [docs/update-signing.md](../update-signing.md).

## Install

Download `v5xs-0.1.3-macOS-26.4-arm64.dmg` from [Releases](../../releases) and drag v5xs into Applications.

**On 0.1.2?** This is the last version you need to download by hand. Starting with 0.1.3, future releases can update automatically.

User-facing guide: [docs/auto-update-guide.md](../auto-update-guide.md).

## Known limitations

- The build is ad-hoc signed, so a manual install may be blocked by Gatekeeper the first time; allow it under System Settings → Privacy & Security. **Automatic updates are unaffected** (files v5xs downloads itself carry no quarantine flag).
- The security boundary for updates is "trust in the maintainer's private key", not "trust in Apple's notarization". Developer ID signing and notarization would allow full code-signature verification.
- Automatic updates do not downgrade; grab an older DMG from Releases if you need one.
- The process list shows individual processes, not whole applications. Terminating a helper such as IDEA's `fsnotifier` will not close the main window — this is expected.
- CPU / GPU temperatures are only read on the validated model (Mac14,2).
